Quick start

About ten minutes. You do not edit any file by hand.

  1. Get your own copy of the baseOn GitHub, open the base repository and click Use this template, then clone your new repository. Keep client repositories private. Or unzip the base into a new folder named for your project.
  2. Open the folder in Claude CodeIn a terminal, cd into the folder and run claude. In VS Code, open the folder, trust it when asked, then click the Claude icon in the sidebar.
  3. Type /start and answer the questionsYour project's name, one sentence on the product, then four clickable choices: retail areas, launch regions, who pays and who uses it daily. Then whether to connect Jira and Confluence. 
    /start
  4. Add what you knowDrop documents, decks, spreadsheets and transcripts into context/00-sources/inbox/, then ingest them. For a web page, give the URL. 
    /ingest context/00-sources/inbox/
  5. Ask the council
    /council Should we add same-day delivery for our top 50 SKUs?
  6. Check what is ready, any time/start status shows a red, amber or green line for each part of the council, and the one next thing to add.

/start checks your computer, sets up git, keeps only the retail areas your product touches (the rest move to archive/ and can be moved back), writes the setup, and shows what is ready.

Base and client projects

One base for all retail work, one copy per client project.

The retail baseAreas, experts, reference players, case studies, failure library, glossary. No client product, no Jira, no Confluence.
copy with /startlearning comes back by pull request
Client project AIts own product, sources, Jira key and Confluence space
Client project BOnly the retail areas it touches
Client project CPrivate repository
  1. CopyCreate the client repository from the base and name it for the engagement.
  2. Set up/start keeps the areas the product touches, writes the Product Lead's product block and offers to connect Atlassian.
  3. FillIngest the client's material. Keep client material out of the base.
  4. Give backA new case study, failure or glossary term that is true across retail goes back to the base through a pull request.

In the base, "our product" is not defined. The council answers for the retail pattern, names the operating model it assumed, and lists what a client project would need to confirm.

Jira and Confluence

Optional. The council never assumes a connection exists, and works without one: drafts are saved as files.

  1. Add the connection/start connect adds Atlassian's server to the project and asks for your Jira project key and Confluence space.
  2. Sign in onceTerminal: exit, run claude again, approve the "atlassian" server if asked, type /mcp, choose atlassian, Authenticate, and sign in in the browser. VS Code: open a new conversation in the Claude panel, approve the server, type /mcp, choose atlassian and sign in.
  3. Confirm/start status. The Jira line should no longer be red.

If the server does not appear or sign-in fails, your Atlassian site admin may need to allow the Atlassian MCP server for your site. Drafts stay local until then.

Modes

/council reads the mode from your request and names it in its first line, for example Mode: solve. Tier 2: a symptom of unknown size. Override with --mode.

The five modes. A mode changes only what it needs before starting, which panels it leans on, and the shape of the round.
ModeYour request sounds likeNeeds before startingDefault panelsRound shape
brainstorm"Ideas for X". No solution yet, no confirmed problemWhich user, which outcome, which part of the journey. A vague theme is refusedproduct, board, industry, competitors, usersAt most 3 ideas per panel, each tied to an evidenced problem. Shortlist 3, cross-examine only those
improve"The checkout flow is clunky". A named existing featureThe feature as it works today, from context or from you. Never imaginedusers, product, competitors, techUser Panel reads today's flow first. Draws today against the pick
solve"Shoppers abandon when payment times out". A symptom of unknown sizeNothingboard, industry, users, techProblem half first (real, who, how often, root cause), a checkpoint on the problem statement, then solutions
validate"Should we build X". A proposal, PRD or designThe proposal, with every assumption tagged V, I or Uboard, product, tech, users, competitorsPanels attack the proposal and never rewrite it
radar"What are we missing"Nothingproblem-radar aloneRanked problems with evidence, no verdict. Saved to reports/problems/

At Tier 2 only the one or two most relevant default panels run. --panels replaces the defaults.

What to say mid-session

You steer the council in plain words at any point.

SayWhat happens
"Go deeper"Moves up one cost tier and reuses the work already done
"Go"Answers a question round with the defaults it offered
"Decide now"Skips any remaining question round and decides on the stated defaults
"About 6 out-of-stock lines per 100 orders"A figure for the data request. The reply says whether it confirmed, changed or flipped the pick
"Continue the substitution analysis"Same as --analysis: picks up that document and builds on it
"Premortem, what if the dark stores never reach density?"That persona answers in character, then the session continues
"Add the user panel, shoppers and pickers only"Brings in a panel mid-session with the personas you name
"How did India and China handle this?"Pulls the matching case studies with their regions and transfer checks
"New fact: we launch in Pune and Jaipur first"Used straight away, then you are asked once: this analysis only, or a curated key fact, rule or background
"No, that was only a proposal"Any correction fixes the output, and a lesson is captured
"A" or "B" when asked about a conflictYour choice goes to the decisions ledger, so it is never asked again
"Draw it" or "compare with today"Draws every flow the pick touches, with today against the pick
"Run the premortem on this"Same as --panels board --only premortem

If something goes wrong

The first problems new users hit and the fix for each.
You seeDo this
"Blocked: ... you are on 'main'"Run python3 scripts/start_project.py branch <topic>, then retry. Shared knowledge only changes on a branch
"Git does not know your name and email"Run the two git config --global lines it prints, then /start again
A hook error mentioning python3On Windows, put python3 on the PATH or run Claude Code in WSL
A slash command is missing in VS CodeType the request in words, or switch the extension to terminal mode
The council says "not in context"That is honest. Add the source with /ingest, then ask again
